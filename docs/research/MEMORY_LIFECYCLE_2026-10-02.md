## Decision proposal

**KEEP the comparative research baseline; ITERATE the bounded unknowns below.**
Maintainer decision is **PENDING**. This document does not adopt an architecture,
implement runtime code, promote WIP, change the roadmap sequence, choose a provider,
or claim a product-quality win. Benchmark applicability: **NOT_APPLICABLE**.

Established controls include search-before-reasoning, after-response capture,
pre-compaction capture requests, local semantic/hybrid retrieval, pluggable vector
storage, source-backed episode provenance, temporal graphs, and persistent core
context. None is a TESSERA novelty claim. Any differentiation from combining
source-backed durable memory, query-conditioned state, evidence sufficiency,
minimum-sufficient context, frozen/disposable work packets and normalized lifecycle
events remains an **inference to test**, not a demonstrated advantage.

## Scope, versions and evidence policy

This is a static read-only source audit. No competitor package was installed or
executed, no competitor source was copied into TESSERA, and no provider request or
paid benchmark was made. Sources were read via the GitHub connector. The initial
repository heads were pinned at 2026-10-02 06:44 UTC; this audit uses those exact
commits rather than claiming to continuously track upstream. Commit snapshots may
include unreleased work. Source hashes fingerprint UTF-8 text normalized to LF,
with trailing end-of-file whitespace removed and one final LF appended; the
manifest records this normalization so fingerprints can be reproduced.

- **inference**: a proposed lesson or consequence drawn from the cited source,
  explicitly not measured or adopted

### Version boundaries that change the answer

1. MemPalace's verified canonical repository is `MemPalace/mempalace`. Its default
   branch is `develop`; hook write routing in this snapshot is explicitly
   unreleased and excluded from v3.6.0 by its own documentation. The older account
   reference in the August notes is superseded, not evidence of current identity.
2. Mem0 OSS SDK, its coding plugin and managed Platform are separate paths. The
   plugin retains local redacted evidence; the current OSS default extraction is
   additive. Neither should be reduced to the historical update-loop description
   or to an extraction-only product with no source evidence. Platform temporal
   boosting is documentation-only here and explicitly excluded from OSS.
3. MemOS Cloud CLI adapters and OSS MemOS/MemCube are separate repositories.
   Schema support in OSS does not establish managed-backend behavior. Cursor's
   adapter captures prompts but explicitly does not inject searched context.
4. `letta-ai/letta` main points to active `letta-ai/letta-code`; its V1 server is
   retired on `archive`. Current prompt/filestore evidence is used here. Historical
   archival-vector assumptions are not substituted for uninspected active code.
5. Graphiti core/MCP are audited; managed Zep parity is unknown. Graphiti source
   contains five distinct edge temporal fields, including `reference_time`, and
   optional raw retention. Queued ingest is not a durable-write receipt.

## Lifecycle-event-layer decision, owned by #177

**Inference / proposed experiment:** evidence from shared MemPalace/Mem0 runners,
MemOS host specs and the native Letta hook executor supports testing a normalized
event layer. It does not establish that every host can deliver every event or
that TESSERA should adopt a competitor's implementation.

The candidate boundary remains:

```text
harness payload → normalized lifecycle event → policy
                  ├─ no-op
                  ├─ retrieve / compile context
                  ├─ capture source evidence
                  ├─ propose durable memory
                  └─ invalidate derived working context
```

| Candidate event | Observed control | Boundary / experiment for #177 |
|---|---|---|
| SESSION_STARTED | MemPalace Codex, Mem0 and Letta types | Bootstrap/readiness is not necessarily retrieval |
| PROMPT_SUBMITTED | Mem0 first-prompt retrieval; MemOS search phase; Letta type | Preserve host scope and capture-only hosts; do not assume retrieval each turn |
| TOOL_STARTED | Letta PreToolUse type | Capture metadata only when available; unknown hosts must not fabricate events |
| TOOL_FINISHED | Mem0 PostToolUse, Letta PostToolUse | Result evidence may be bounded/redacted; distinguish observed result from intended action |
| TOOL_FAILED | Mem0 failure adapter, Letta failure type | Separate actual failure event from missing final result |
| CONTEXT_COMPACTING | MemPalace, Mem0 and Letta types | Triggering a flush is not proof it completed before compaction |
| RESPONSE_FINISHED | MemPalace/Mem0 Stop; MemOS add phase; Letta Stop | Repeat-safe receipt independent of the harness stop/continue decision |
| SESSION_FINISHED | MemPalace Claude, Mem0, Letta type | Best-effort end signals can be missing; define recovery without relying on final callback |
| FEEDBACK_RECEIVED | MemOS metadata includes feedback update type; Letta prompt encourages learning | **Unknown** as a distinct normalized host callback in this audit. Model as a proposal until #177 proves a host source and #168 defines admission |

**Counterevidence to a uniform abstraction:** MemOS Cursor capture without
injection, Mem0 first-prompt-only automatic search, different MemPalace manifests,
and explicit Graphiti MCP calls all show why a single universal event promise
would be misleading. Event receipt, policy decision and durable completion need
separate records. A normalized event must not itself authorize tool execution,
source mutation or LLM admission.

## Validation and limitations

The research validator checks 5 systems × 10 unique dimensions, per-claim
code/docs/inference/unknown labels, resolvable source IDs, immutable 40-character
commit links, complete required CSV columns and routing only to existing #179
owners. It checks structure, not truth. Human source review remains necessary.
The TESSERA regression suite is run separately; its results are recorded in the
[stage record](../test-cards/179-memory-lifecycle-research.md). No external system
was runtime-tested, no marketing benchmark was reproduced and no superiority
inference is warranted. Research review does not change the product version,
public API, semantic drawers, index format or basic-path LLM requirements.
