# LongMemEval-V2 offline conformance preparation (#106)

**Draft preparation; official conformance is false and evaluation is NOT_RUN.**
This package is repository-only, excluded from wheel/sdist. It imports the existing
TESSERA Engine but changes no production code, retrieval policy or dependencies.
Issue [#106](https://github.com/LuigiFerronatto/TESSERA/issues/106) remains BLOCKED
on canonical #74/#100/#103/#104/#105 acceptance. This does not select the full
card, consume unmerged implementations, unlock dependents, or establish KEEP.

## What runs offline

An original, invented fixture has two independent domain haystacks, three total
states, three original one-pixel PNG sources, and a separate synthetic query
image. Its literal text and assets contain no official data or model output.

- Public `states` trajectory form is validated and copied in full. Unknown
  fields fail closed at trajectory/state boundaries. Every state becomes one
  temporary Markdown source with goal, outcome, URLs, action, thought and tree;
  all original fields remain in the deep-copied trajectory snapshot and hashes
- An isolated `SyntheticTesseraMemory` instance uses unmodified TesseraEngine
  retrieval on that temporary corpus. No official backend registration/import
  or runner is provided
- `query(query, query_image=None)` accepts only text and an optional source
  path. The synthetic query image is verified but **does not influence retrieval**
- Output items contain exactly `type` and non-empty `value`. Synthetic source
  PNGs are validated against their exact generated bytes, with a bounded read;
  unsupported/corrupt/missing images fail explicitly. This is deliberately not
  a general-purpose image decoder or multimodal retriever
- Provenance is separate from reader context: trajectory ID, state index,
  original step, trajectory/state/image hashes and source-image relative path
  survive insertion and emitted-prefix selection
- Synthetic budget costs are 7 units per text item, 11 per image, plus 2 for
  a nonempty sequence. Those constants exercise **only budget mechanics**, never
  tokenizer accuracy. Prefix selection preserves whole items and their order
- Each instance owns a fresh temporary haystack. Insertion is sealed after the
  first query; another domain or haystack needs another instance. Query-local
  trace state is thread-local and cleared even after an exception. The opaque
  invocation ID never enters Engine query text, configuration or stored documents
- An evaluator-side projection inspects only `question`; sentinels demonstrate
  that ID/type/answer/raw record/evaluator configuration are never passed to the
  adapter. Structural guards cannot detect an answer hidden inside allowed prose;
  a trusted source boundary is still required

Save/load is explicitly unsupported. Original images are source evidence: no
OCR, caption, embeddings, generated descriptions or derived vision text exists.
Text-only output is a transport ablation, not a full official benchmark arm.
The adapter is serial fixture tooling; concurrent insertion or retrieval is not
promised. Thread-local trace tests do not imply concurrent Engine safety.

## Commands

From an external development virtual environment with `.[dev]` installed:

```bash
python -m pytest -q tests/test_v2_conformance_preparation.py
python -m benchmarks.longmemeval_v2.cli --output-dir /tmp/v2-synthetic-a
python -m benchmarks.longmemeval_v2.cli --output-dir /tmp/v2-synthetic-b
cmp /tmp/v2-synthetic-a/conformance.json /tmp/v2-synthetic-b/conformance.json
cmp /tmp/v2-synthetic-a/manifest.json /tmp/v2-synthetic-b/manifest.json
```

Use new output directory names. Clean source is required unless the explicit
`--allow-dirty-worktree` preparation override is supplied; that fact is recorded.
Outputs must be outside checkout or under ignored `artifacts/longmemeval-v2/`.
The CLI writes only a compact synthetic manifest/report; it never creates an
`answers.jsonl`, official scorecard or quality metric. Full suite/build/sanity
and exact-head Benchmark Ledger are separate preservation gates.

## Official execution is still blocked

The audited processor constructor resolves mutable `Qwen/Qwen3.5-9B` and does
not specify an immutable revision. This package does not install transformers,
Pillow, torch or an OpenAI SDK. `bound_context(..., counter=None)` raises
`official_tokenizer_unpinned`, even for an empty context. Selecting an official
profile raises `official_execution_not_supported`. There is no tokenizer
fallback, credential lookup, endpoint, download path or official execution CLI.

Future work needs accepted dependencies and protocol review, immutable processor
and reader/judge identities, general image decoding and content verification,
a licensed checksum-verified dataset cache, bounded resource/cost authorization,
and compatible official small-tier runs in both domains. Medium needs a separate
KEEP/resource decision. The metadata-only advertised dataset size is 7,120,369,667
bytes; none of the corpus, screenshots or model assets was downloaded here.

PR [#315](https://github.com/LuigiFerronatto/TESSERA/pull/315) renderer preparation
and [#321](https://github.com/LuigiFerronatto/TESSERA/pull/321) reader preparation
were inspected as unmerged contracts. This V2 profile does not import them,
reuse their text-token policy, manufacture their reader messages, or append
V2 outcomes to the closed #100 V1 retrieval ledger. Any future V2 reader bridge
must carry the upstream multimodal prompt unchanged after proper token counting.

See [protocol audit](protocol-audit.md), [source pins](protocol.json), and the
